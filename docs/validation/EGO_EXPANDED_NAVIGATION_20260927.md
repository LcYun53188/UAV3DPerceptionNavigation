# 扩展场景 RViz 导航修复验证（2026-09-27）

问题：RViz 目标已到达规划器，但原目标 `(7.99,4.25,1.2)` 持续触发
`REJECT_CURVE_COLLISION`。EGO 平滑后的曲线没有通过独立机体碰撞检查，因此没有向执行器发送轨迹。

修复：A* 种子增加半体素余量；优化失败或平滑曲线不安全时，对原种子做经过碰撞检查的捷径简化，
生成在航点处速度、加速度归零的三次 B 样条。回退路线仍通过完整碰撞检查、动态限制、时效和时长检查，
执行器再次用 SciPy 独立校验。回退状态为 `SAFE_SEED_FALLBACK`，未放宽未知区策略或机体半径。
规划器状态变化也会写入日志，避免失败只出现在话题中。

在 `uav_ego_expanded.sdf` 与地图 `.cache/maps/uav_ego_expanded_20260926` 上实测：

- 原目标：从 `(-7.5,-7.5,1.2)` 出发，回退轨迹用时约 133 秒，收到 `ACCEPTED` 和 `GOAL_REACHED`；终点误差约 0.00074 m。
- 独立按扩展场景 SDF 中的柱体、箱体、隔墙、门框、围墙及地面几何计算，0.3 m 机体包络的最小实际余量约 0.261 m。
- 短目标 `(7.99,3.25,1.2)`：直接使用优化轨迹，时长约 4.24 秒，到达误差约 0.00181 m。
- 障碍物内目标 `(0,0,1.2)`：返回 `BLOCKED_START_OR_GOAL`，没有发布轨迹，实测位移为 0；取消后恢复等待目标。
- `src/uav_nav_sim/test` 的 27 项测试通过。

结果见 [JSON](EGO_EXPANDED_NAVIGATION_20260927.json)。从扩展场景初始位姿、已加载地图且目标高度 1.2 m 时，可复现：

```bash
ROS_DOMAIN_ID=68 ./scripts/with_venv.sh python scripts/check_gazebo_expanded_goal.py \
  --goal 7.99 4.25 --timeout 240 --output /tmp/expanded_navigation.json
```

该脚本通过 RViz 同一输入话题发送目标，并核对轨迹、实际到达及场景几何间距。
它只适用于这个扩展场景。回退会在航点停顿，因此比连续平滑轨迹慢；只固定终点高度，
本次绕障路线中间最低高度约 0.8 m。验证对象仍为无飞控 Gazebo 速度模型，不是实机飞行。
